# postlens: performance analysis for your own posts

**Turn the post data you exported from a platform into engagement scores, group it by topic and opening style, and write a Markdown report.**

Reads local files only, no network access, zero dependencies (Python standard library). The question it answers:
"Which of my topics, openings and posting times perform better?"

> The "scraper" in this repository's name is left over from early notes. It now contains **no scraping features**.
> See "Where the data comes from" below.

## Quick start

Python 3.10+, nothing to install. Run it on the bundled fictional sample:

```bash
python -m postlens analyze examples/sample_posts.csv --rules rules.example.json --out out
```

```text
analyzed 36 of 36 posts
wrote out\report.md
wrote out\posts_scored.csv
wrote out\summary.json
```

The report groups posts by topic, opening style, weekday and three-hour slot, lists the top 10 posts, and ends with
interpretation limits. Report labels are in Traditional Chinese.

## Where the data comes from

Only analyze data **you have the right to use**:

| Source | How to get it | Usage |
|---|---|---|
| X (Twitter) account archive | Settings → Your account → Download an archive of your data; use `data/tweets.js` | `python -m postlens analyze data/tweets.js` |
| Official platform APIs | Call the official API with your own account's authorization (for example Threads API posts and insights) and save JSON | a list or `{"data": [...]}` |
| Platform data downloads, dashboards | Export CSV or JSON | column names below |
| Manual | Build your own CSV | needs at least a time column |

This project does **not** provide, and will not accept, features or instructions for: scraping web pages, automated
login, bypassing CAPTCHAs or anti-bot protection, evading rate limits, or collecting other people's account data
without consent.

X archives carry no reply or view counts; the report says so. Reposts (`RT @…`) are excluded unless you pass `--include-reposts`.

## Columns

CSV and JSON share one alias table, case-insensitive; numbers may contain thousands separators.

| Field | Accepted names | Required |
|---|---|---|
| time | `created_at` `timestamp` `date` `time` `published_at` `posted_at` | yes |
| text | `text` `full_text` `content` `message` `caption` `body` | |
| likes | `likes` `like_count` `favorite_count` `favorites` `reactions` | |
| replies | `replies` `reply_count` `comments` `comment_count` | |
| reposts | `reposts` `repost_count` `retweets` `retweet_count` `shares` `share_count` | |
| quotes | `quotes` `quote_count` | |
| views | `views` `view_count` `impressions` `impression_count` | |
| id | `id` `id_str` `post_id` `media_id` | |
| link | `url` `permalink` `link` | |

## How it calculates

- **Engagement score** = likes×1 + replies×1.5 + reposts×2 + quotes×2 (weights configurable)
- **Engagement rate** = (likes + replies + reposts + quotes) ÷ views; skipped, not zero, when views are missing
- **Percentile** of each post within the dataset, ties share the average rank
- Group statistics lead with the median; groups under 5 posts are marked as small samples and sorted last

## Rules file

`rules.example.json` sets weights, topics (matched against the full text, multi-label) and hooks (first line only,
first matching rule wins). `keywords` are case-insensitive literals; `patterns` are regular expressions.

## Options

`--format auto|csv|json|x-archive`, `--rules`, `--out` (default `out`), `--utc-offset` (default `+08:00`),
`--since` / `--until` (start inclusive, end exclusive), `--include-reposts`.

Exit codes: `0` success, `1` no posts after filtering, `2` input or option error (messages name the file and row).

## Limits

- Topics and hooks are keyword rules, not semantic understanding.
- The report shows correlation, not causation.
- `examples/sample_posts.csv` is fictional, generated by `examples/make_sample.py` with a fixed seed.
